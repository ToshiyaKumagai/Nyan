## 次にやること（順に）

1. 案件の入力の所在を受け取る：案件ページ URL、タスク表、論点シート、IT基盤の進捗、Slack チャンネル（案件ページのプロパティに無ければ）
2. `skills/progress/SKILL.md` に沿って `--dry-run`。18節目の状態と週次レビューの下書きを出し、人が全部読む
3. 評価の規約（`progress` の表）を1回目の結果で直す。直すのは `skills/progress/SKILL.md` だけ。理由を `CHANGELOG.md` に1行
4. 書き込み → フロントのレビュー（表の「コメント」の列かページのコメント）→ `--review` で反映、を1周
5. `notify` の下書きを見て、初回投稿
6. `evals/` にケースを置く（`claude plugin eval`）

## 守ること

- 判断できる情報が無ければ判断しない。週次レビューの「AIで判断できないものへのレビュー」に置く
- 根拠 URL の無い○×を付けない。無いことを × にしない
- 本体はページ、プロパティは要約。マイルストーンページは状態・事実の列だけを置き換え、更新履歴は追記のみ。評価は週次レビューへ
- 人の書き込みを上書きしない。レビューを受けて直すのは nyan
- 案件固有の値と Slack の投稿先をリポジトリに書かない
- 標準の写しを手で直さない。直すなら donyu-standard に PR
