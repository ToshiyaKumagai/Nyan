# 導入マイルストーンDB を読む・書く（ツール層）

## 原本DB（固定値）

| DB | データベースURL | data_source_id |
| --- | --- | --- |
| 導入マイルストーンDB | https://app.notion.com/p/d483c197b35c41ba97cecc35f424b2bb | `collection://cbe6fa41-09ec-4aa7-90a9-7e1bd3f8f10b` |

原本DBは1本だけなので ID は固定値として使う。毎回受けるのは**案件ページの ID** だけ。マイルストーンは原本DBだけで管理し、案件ページ・子ページにマイルストーンのビューは無い。

## プロジェクトの特定

`tool-notion-minutes` の「プロジェクトの特定」と同じ（案件ページIDを正規化し、`"プロジェクト" LIKE '%<ハイフン無し32桁>%'` で絞る）。案件ページの配下に旧DBが残っていたら、読まずに「未移行の案件」として返す。

## スキーマ（2026-09-27 時点）

| プロパティ | 型 | 書き方 |
| --- | --- | --- |
| マイルストーン | タイトル | 標準の18件の呼称（`flow-donyu` の対応表）。**変えない** |
| プロジェクト | リレーション | 案件ページへの片方向リレーション。書くときは `["<ページIDのハイフン付きUUID>"]` |
| 順序 | 数値 | 1〜18。**標準カードを引く鍵**。変えない。予定時期で代用しない。小数（例 7.5）は案件固有のマイルストーンで、対応するカードが無い |
| 予定時期 | 日付（範囲可） | 実績または予定。プロセスが根拠つきで明示したときだけ書く。根拠が無ければ空にする |
| Status | セレクト | 未着手／準備中／進行中／完了／対象外 |
| ギャップ | テキスト | 1〜2文の要約 |
| 打ち手 | テキスト | 1〜2文の要約 |
| AI処理日時 | 日付（時刻あり） | AI が本文を書いた日時。書いたら必ず入れる |
| 週次レビュー | リレーション（双方向） | 対象にした週次レビュー。週次レビュー側の「対象マイルストーン」を書けば入る |
| 評価の推移 | ロールアップ | 週次レビューの評価を集めたもの。読むだけ（SQL では引けない） |

DB には `評価` のセレクト列も残っているが、nyan は**書かない**（評価は週次レビューに書く。`tool-notion-weekly-review`）。

日付の書き方：`date:<列>:start` ＋ `date:<列>:is_datetime`（日付だけなら 0、時刻ありなら 1 で `+09:00` 付き ISO）。範囲なら `date:<列>:end` も入れる。

## 標準カードを引く

`順序` の値で `flow-donyu` の「順序 ↔ 標準カード」の対応表を引き、`references/cards/<カード>.md` を開く。順序が空・小数・表に無い値のときは「カード無し」と返し、推測で結ばない。

## 本文の形

```
> 判定の基準：donyu-standard <カードID>. <カードのH1>（標準の版はプロジェクトページに1回書く。標準の写しはこのページに置かない）
## 受け入れ条件
<table>  列：カテゴリ｜主語｜受け入れ条件｜期限（逆算の観点）｜状態｜事実（根拠）｜コメント
状態：○＝達成の根拠あり／×＝未達の根拠あり／未確認＝根拠なし／対象外
## 理想状態
<table>  列：カテゴリ｜主語｜理想状態｜事実（根拠）｜コメント
## 更新履歴
- YYYY-MM-DD：<何を根拠に何を書いたか>
```

- 引用行・表の見出し・「状態：…」の注記の文言は固定。それ以外の説明文・注意書き・メタコメントを本文に入れない
- 受け入れ条件と理想状態の表の**行はカードから写す**。受け入れ条件の「期限（逆算の観点）」はカードの逆算の観点の列、「対象外（理由）」の行は状態を「対象外」にして残す。理想状態の表は、カードで主語が「—」の行を写さない
- 状態の値は ○／×／未確認／対象外 の4つだけ
- @メンションを使わない。人名は文字で書く
- 実例：https://app.notion.com/p/a697fab7f4e682c1936a0106f861aecc 、https://app.notion.com/p/3e87fab7f4e681e799d3d921d9dedaf7

| 部分 | 扱い | 誰が書く |
| --- | --- | --- |
| 受け入れ条件の表の「状態」「事実（根拠）」、理想状態の表の「事実（根拠）」 | **最新の断面に置き換え**（セル単位） | nyan |
| 表の「カテゴリ」「主語」「受け入れ条件」「期限」「理想状態」 | カードから写したまま。変えない | nyan（初回に写す） |
| 表の「コメント」 | **触らない** | 人 |
| 更新履歴 | **追記のみ** | nyan |

評価・ギャップの説明・事実確認・タスクはこのページに書かない（週次レビューに書く）。

## 読む

- 一覧：`notion-query-data-sources`（SQL）で案件の全行

```sql
SELECT "マイルストーン", "順序", "Status", "date:予定時期:start", "date:予定時期:end",
       "ギャップ", "打ち手", "date:AI処理日時:start", url
FROM "collection://cbe6fa41-09ec-4aa7-90a9-7e1bd3f8f10b"
WHERE "プロジェクト" LIKE ?            -- '%<ページIDのハイフン無し32桁>%'
ORDER BY "順序"
```

- 本文：`notion-fetch`。人の指摘は、表の「コメント」の列と、ページのコメント（`include_discussions` を立てて fetch → `notion-get-comments`）の両方を読む

## 書く

1. **書く前に読む。** 直前に `notion-fetch` で現在のプロパティと本文を取る。前回 nyan が書いた値と違えば、人の変更として呼び出し元に返し、その値を起点にする（上書きしない）
2. **置き換え。** `notion-update-page` の `update_content` で、対象の行のセル（状態・事実（根拠））を `old_str` → `new_str` で差し替える。`old_str` は**直前に fetch した本文からそのまま取る**（Notion 側の表記揺れで、記憶やカードの文面では一致しないことがある）。他の行・列・節に触れない
3. **追記。** 更新履歴の末尾に `insert_content`（位置は更新履歴の最後の行の直後）で1行足す。既存の行は変えない
4. **プロパティ。** `update_properties` で Status・予定時期・ギャップ・打ち手・AI処理日時
5. **読み戻す。** `notion-fetch` で、置き換えたセルだけが変わり・更新履歴が1行増えただけで・コメントの列と他の行が無傷であることを確かめる。崩れていたら報告して止まる（重ねて書かない）

## しないこと

- 行（ページ）を消す／表の行を消す
- マイルストーンのタイトルと順序を変える
- 評価を書く（週次レビューへ）／本文に評価・ギャップの説明・事実確認・タスクの節を作る
- 「コメント」の列を書き換える／更新履歴を書き換える
- 18行に足りない行を勝手に作る（提案を返す）
- 予定時期にテンプレートの仮の日付を入れる
- 列や選択肢を足すなどのスキーマ変更（必要なら提案を返す）
