# 差分 → Slack（プロセス層）

引数：`$ARGUMENTS`。参照：投稿 → `tool-slack-post`／節目の指し方 → `flow-donyu`／その週のレビュー → `tool-notion-weekly-review`／更新履歴への追記 → `tool-notion-milestone-db`

## 投稿先（リポジトリに持たない）

1. 引数で指定されたチャンネル
2. 無ければ、案件ページのプロパティの Slack チャンネル（例 `#proj-○○病院様`）を候補にし、**確認を取る**。プロパティに無ければ案件ページの医療機関名で検索し、候補を示して確認を取る
3. 見つからなければ利用者に聞く。初期値は持たない

## メッセージの型（5つの塊は固定。空なら「なし」）

```
【<医療機関名>】マイルストーン進捗の更新（M/D。根拠：StandUp M/D・M/D、タスク表 M/D 時点）

■ 要介入（🔴）
・<マイルストーン（タイトル）>：<未達の条件>。打ち手の案：…（受け皿：…）→ 議論の場を設ける

■ 要観察（🟡）
・<マイルストーン>：<根拠が無い／曖昧な条件> → 方針を求める

■ 事実確認をお願いしたいこと
・<何を・なぜ・誰に>

■ タスク
・更新されていない：<タスク>（<議事録 M/D> で完了と読める）
・次にやるべき：<マイルストーン> → <タスク>（目安 M/D まで）

Notion：<その週の週次レビューのページ URL>
```

- マイルストーンは導入マイルストーンDBのタイトル（標準の18件の呼称）で書く。ID は書かない
- リンクはマイルストーンDBではなく、その週の週次レビュー（読み手が開くのはレビュー）。`tool-notion-weekly-review` の「読む」で直近のレビューを取る
- 1回の実行で1本。詳細はスレッド
- 顧客の PII を書かない。「〜が理解している」のような観測できない言い回しを使わない

## 手順

1. 投稿先を決める（上）
2. 文面を組み、`tool-slack-post` で下書きとして見せる
3. 承認されたら投稿し URL を返す。差し戻しは直して 2 へ
4. 投稿 URL を、その週のレビューの「対象マイルストーン」の各ページの「更新履歴」の末尾に追記する（`tool-notion-milestone-db`）。週次レビューには追記しない（追記の節を持たない）

## しないこと

- 承認なしの投稿／同報／評価の変更（変えるなら `progress` をやり直す）
- 週次レビューの本文を書き換える
