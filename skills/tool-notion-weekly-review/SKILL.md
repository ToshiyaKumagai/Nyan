# 導入週次レビューDB を読む・書く（ツール層）

## 原本DB（固定値）

| DB | データベースURL | data_source_id |
| --- | --- | --- |
| 導入週次レビューDB | https://app.notion.com/p/8c0c732100a746c09d743f12043a9dc9 | `collection://b7af7057-926e-46ab-8b2c-dd2c360bf435` |

原本DBは1本だけなので ID は固定値として使う。毎回受けるのは**案件ページの ID** だけ。子ページ「【○○病院様】StandUP&プロジェクト議事録一覧」の「今週のレビュー」は、このDBのリンクドビュー（プロジェクト＝自身 かつ AI処理日時が過去3週間）。

## プロジェクトの特定

`tool-notion-minutes` の「プロジェクトの特定」と同じ（案件ページIDを正規化し、`"プロジェクト" LIKE '%<ハイフン無し32桁>%'` で絞る）。

## スキーマ（2026-09-27 時点）

| プロパティ | 型 | 書き方 |
| --- | --- | --- |
| 週次レビュー | タイトル | 「<直近のマイルストーン>まであと<N>日」（下の「タイトルの決め方」） |
| プロジェクト | リレーション | `["<案件ページIDのハイフン付きUUID>"]` |
| レビュー日 | 日付 | レビューを作った金曜。`date:レビュー日:start` ＋ `date:レビュー日:is_datetime: 0` |
| 評価 | セレクト | 🔴 要介入／🟡 要観察／🟢 経過観察。値はプロセスが決めて渡す |
| 要注意ポイント | テキスト | 一覧で読む一行（改行は `<br>`） |
| 対象マイルストーン | リレーション（双方向） | 直近のマイルストーンと、並行して進行中のもの（導入マイルストーンDBのページ URL の配列）。マイルストーン側の「週次レビュー」に自動で入る |
| AI処理日時 | 日付（時刻あり） | **必ず入れる**。`date:AI処理日時:start`（`+09:00` 付き ISO）＋ `date:AI処理日時:is_datetime: 1`。空だと子ページのビューに出ない |

- `評価` の値は選択肢と一字一句同じに書く。**DB の選択肢が上の3つと一致しないときは、評価を書かずに止め、選択肢の変更を提案として返す**（無い値を書くと選択肢が勝手に増える）
- 列や選択肢を足すなどのスキーマ変更はしない（必要なら提案を返す）

## 読む

直近のレビュー：

```sql
SELECT "週次レビュー", "date:レビュー日:start", "評価", "要注意ポイント",
       "対象マイルストーン", "date:AI処理日時:start", url
FROM "collection://b7af7057-926e-46ab-8b2c-dd2c360bf435"
WHERE "プロジェクト" LIKE ?            -- '%<ページIDのハイフン無し32桁>%'
ORDER BY "date:レビュー日:start" DESC
LIMIT 1
```

本文は `notion-fetch`。同じ週（同じレビュー日）の行があるかも、この SQL に `AND date("date:レビュー日:start") = date(?)` を足して確かめる。

## 書く

1. **同じ週の行があるか確かめる。** 1週＝1行。同じレビュー日の行が既にあれば、新しい行は作らず、その行を更新する（`notion-update-page`。`old_str` は直前に `notion-fetch` した本文から取る）
2. **新規行。** 無ければ `notion-create-pages` で、親を data_source `b7af7057-926e-46ab-8b2c-dd2c360bf435` にして1行作る。プロパティは タイトル・プロジェクト・レビュー日・評価・要注意ポイント・対象マイルストーン・AI処理日時 の7つを**すべて**入れる
3. **読み戻す。** `notion-fetch` で、プロパティが7つとも入り、本文が下の型のとおり（節の見出し・順序・注記の文言）であることを確かめる。崩れていたら報告して止まる

過去の週のレビューは書き換えない。

## タイトルの決め方

- 「<直近のマイルストーン>まであと<N>日」。マイルストーンは導入マイルストーンDBのタイトル（標準の18件の呼称）で書く
- N はレビュー日から直近のマイルストーンの予定時期の開始日までの日数（例：レビュー日 9/25、リハーサル① 9/29 → 「リハーサル①まであと4日」）
- 直近に2つ重なる週は、先に来る方だけを書く
- **日付を入れない**

## 本文の型（節の見出し・順序・注記の文言は固定）

```
<callout icon="📍" color="blue_bg">
	<span color="gray">直近のマイルストーン</span>
	### <マイルストーン>（<日付>、あと<N>日）
	並行して進行中：<マイルストーン>（<一言>）
	**本番稼働まで**：あと<N>週（<日付>）
	**今週の評価**：<評価> — <一文>
</callout>
## 今週までの簡単なサマリー {color="gray_bg"}
<span color="gray">色はチェックリストと連動しています。🟡はチェックリストに論点があるもの、🔴は期日への影響が避けられないものです。</span>
- 🟢/🟡/🔴 **運用構築**：…
- 🟢/🟡/🔴 **電子カルテ設定**：…
- 🟢/🟡/🔴 **操作習熟**：…
- 🟢/🟡/🔴 **データ移行**：…
- 🟢/🟡/🔴 **ハードウェア・ネットワーク**：…
- 🟢/🟡/🔴 **システム連携**：…
- 🟢/🟡/🔴 **会議体の準備**：…
## 今のマイルストーンに対するチェックリスト {color="gray_bg"}
#### 未達成項目へのレビュー {color="gray_bg"}
<span color="gray">記録からは「できている」と言い切れないものです。StandUpで、完了・やらなくてよい理由・打ち手のどれかに着地させてください。緊急度の高い順です。</span>
1. **<問いの形の一文>**
	- 理由：…
	- StandUpで決めたいこと：…
#### AIで判断できないものへのレビュー {color="gray_bg"}
<span color="gray">議事録・Slackに記録が見つからず、AIには判断できなかったものです。できているかを確かめてください。</span>
1. **<問いの形の一文>**
	- 理由：…
	- StandUpで決めたいこと：…
## 全体を通しての懸念点 {color="gray_bg"}
<span color="gray">この先の予定から逆算して、頭の片隅に置いておいてほしいことです。今週決める必要はありません。緊急度の高い順です。</span>
- **<見出し>**：…
## 根拠にした議事録 {color="gray_bg"}
- <議事録の会議体と開催日>、<Slack のチャンネルと期間>、<シート名と時点>
---
<span color="gray">このレビューはAIが議事録とマイルストーンDBをもとに作成する。人は書き換えず、金曜のStandUpで議論した内容は議事録に残す</span>
```

- サマリーは7領域をこの順で必ず7行。該当が無い領域も行を残す
- 「未達成項目へのレビュー」は状態が×の受け入れ条件、「AIで判断できないものへのレビュー」は状態が未確認の受け入れ条件。番号付きで、各項目は「理由」「StandUpで決めたいこと」の2行。0件なら「なし」
- StandUp で結論が出たことを同じ週に反映するときは、その項目の末尾に `- **M/Dの結論：<結論>（決定／宿題）**` の1行を足す。出どころは議事録
- 各事実に出どころを添える（例「（9/24 StandUp）」「（9/17 Slack）」）
- 上の見出しと注記以外の説明文・案内文を足さない。@メンションを使わない（人名は文字で書く）
- 実例：https://app.notion.com/p/3e87fab7f4e68149a997e6f2379d9a66 、https://app.notion.com/p/3e87fab7f4e6819487d4f0ca6fcb12e4 、https://app.notion.com/p/3e87fab7f4e6814c92a3ecd21eaad244

## しないこと

- 評価・○×・緊急度を決める（プロセスが渡した値を書くだけ）
- 過去の週のレビューを書き換える／同じ週に2行目を作る
- AI処理日時・対象マイルストーン・プロジェクトを空のまま作る
- スキーマの変更（選択肢を足すことを含む）
