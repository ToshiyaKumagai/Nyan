# 導入議事録DB を読む（ツール層）

## 原本DB（固定値）

| DB | データベースURL | data_source_id |
| --- | --- | --- |
| 導入議事録DB | https://app.notion.com/p/b5bbfcbdabb54146b68748e2e9163c75 | `collection://27b4e3d9-fb28-400a-ac4a-0e0240cf4fe2` |

原本DBは1本だけなので ID は固定値として使う。毎回受けるのは**案件ページの ID** だけ。

## プロジェクトの特定

1. 引数で案件ページ（PTS Project の1ページ「【○○病院様】導入プロジェクト」）の URL か ID を受ける。子ページ（「【○○病院様】StandUP&プロジェクト議事録一覧」）の URL を渡されたら、`notion-fetch` で親の案件ページに辿る
2. ページIDを UUID 形式（ハイフン付き）に正規化する
3. SQL では `"プロジェクト" LIKE '%<ページIDのハイフン無し32桁>%'` で絞る（リレーション列は URL の JSON 配列で返るため）

子ページのリンクドビューは表示のためのもので、クエリには使わない。

### 未移行の案件

案件ページか子ページの配下に、案件ごとの旧DB（インラインの議事録DB・マイルストーンDB）が残っていたら、**読まずに**「未移行の案件」として返す。旧DBは置き場へ退避済みで、参照しない。

## スキーマ（2026-09-27 時点）

| プロパティ | 型 | 使い方 |
| --- | --- | --- |
| 会議名 | タイトル | **日付を入れない**。一意な会議体は会議体名そのもの（例「社内キックオフ」「StandUp」）、連番の会議体は対象部署・テーマだけ（例「外来」「LSI検査連携・端末見積もり」）。日付は開催日で見る |
| 会議体 | セレクト | 下の選択肢 |
| 区分 | セレクト | 社内（病院が参加しない会議）／社外（病院が参加する会議） |
| 開催日 | 日付 | 絞り込みの軸。SQL では `date:開催日:start`。未開催の回は予定日が入っている |
| AIサマリ | テキスト | 一文の要約。**本文の代わりにしない**（決定の一部しか載らない） |
| AI処理日時 | 日付（時刻あり） | AI が最後にこの議事録を処理した日時 |
| プロジェクト | リレーション | PTS Project（案件ページ）への片方向リレーション |

会議体の選択肢（この並び順・区分で固定）：

- 社内：StandUp／社内キックオフ／アセスメント事前すり合わせ／データ調査・移行検討／アセスメント引き継ぎ／IT基盤社内打ち合わせ／社内打ち合わせ（その他）
- 社外：アセスメント／全体キックオフ／部署別ヒアリング／部署別キックオフ／運用検討部会❶／運用検討部会❷／運用検討部会❸／病棟部会／操作研修（基礎編）／操作研修（応用編）／リハーサル❶／リハーサル❷／医事課定例／ベンダー・IT連携／先行運用／オーナー会議／電子カルテ委員会／顧客打ち合わせ（その他）

## 絞り込み

`notion-query-data-sources`（SQL）でプロジェクトと開催日の範囲を絞り、URL の一覧を取る。社内・社外は `区分` で絞れる（どちらを読むかは呼び出し側が決める）。

```sql
SELECT "会議名", "会議体", "区分", "date:開催日:start", "AIサマリ", url
FROM "collection://27b4e3d9-fb28-400a-ac4a-0e0240cf4fe2"
WHERE "プロジェクト" LIKE ?            -- '%<ページIDのハイフン無し32桁>%'
  AND date("date:開催日:start") >= date(?)
  -- AND date("date:開催日:start") <= date(?)   -- 未開催の予定（開催日に予定日が入った行）を除くとき
  -- AND "区分" = '社内'
ORDER BY "date:開催日:start"
```

本文はページごとに `notion-fetch`。AIサマリが「内容なし」の回は開かなくてよい。

## 本文の節構成（テンプレートから生成された議事録の場合）

| 節 | 何が書かれているか | 読む優先 |
| --- | --- | --- |
| 会議情報 | 日時・参加者 | 低 |
| 議題・論点ごとの議論内容 | 議題ごとの経緯と「結果」 | 中（決定事項の裏取り） |
| 決定事項 | 番号付きの決定 | **高** |
| 宿題・TODO | 担当と期限の無いことが多い | 高（未確認の候補） |
| スケジュール・今後の予定 | 確定日程／検討中 | **高**（予定時期の食い違いの検出） |
| アジェンダ・共有メモ（原文） | 会議前のメモ | 低 |

古い議事録は Notion のミーティングノート（文字起こし）だけで、この節構成が無いことがある。その場合は本文全体を読む。

## 返す形

事実1件＝1行で、`開催日｜会議体｜事実（一文）｜議事録 URL`。解釈や評価を混ぜない。本文は原文のまま読み、要約・言い換えで事実を変えない。

## 制約

- 顧客の PII が本文にあっても、返す事実に写さない（医療機関名は可）
- 書き込みはしない。会議体の選択肢を足すなどのスキーマ変更が要ると判断したら、提案として返す
