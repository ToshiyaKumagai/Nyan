# 社内議事録 DB を読む（ツール層）

## 場所の辿り方

1. 渡されたプロジェクトページ（例：「【○○病院様】StandUP&社内打ち合わせ」）を `notion-fetch` で開く
2. 本文の `<database inline="true">` のうち、タイトルが「社内の議事録一覧」のものが議事録 DB。同じページにある「マイルストーン進捗」は別のツール（`tool-notion-milestone-db`）が扱う
3. 議事録 DB を `notion-fetch` で開き、`<data-source url="collection://…">` の URL とスキーマを取る。**URL はページごとに違う**ので毎回取り直す（ハードコードしない）

## スキーマ（2026-09-24 時点の吉見病院の例。列が違えばこちらを直す）

| プロパティ | 型 | 使い方 |
| --- | --- | --- |
| 会議名 | タイトル | 「YYYY-MM-DD_StandUp」の形。日付は開催日で見る |
| 会議体 | セレクト | StandUp（社内定例）／社内キックオフ／データ調査・移行検討／アセスメント引き継ぎ／その他 |
| 開催日 | 日付 | 絞り込みの軸。SQL では `date:開催日:start` |
| AI サマリ | テキスト | 一文の要約。**本文の代わりにしない**（決定の一部しか載らない） |

## 絞り込み

`notion-query-data-sources`（SQL）で開催日の範囲を絞り、URL の一覧を取る。

```sql
SELECT "会議名","会議体","date:開催日:start",url
FROM "collection://<data-source-id>"
WHERE date("date:開催日:start") > date(?)
ORDER BY "date:開催日:start"
```

本文はページごとに `notion-fetch`。AI サマリが「内容なし」の回は開かなくてよい。

## 本文の節構成（テンプレートから生成された議事録の場合）

| 節 | 何が書かれているか | 読む優先 |
| --- | --- | --- |
| 会議情報 | 日時・参加者 | 低 |
| 議題・論点ごとの議論内容 | 議題ごとの経緯と「結果」 | 中（決定事項の裏取り） |
| 決定事項 | 番号付きの決定 | **高** |
| 宿題・TODO | 担当と期限の無いことが多い | 高（未確認の候補） |
| スケジュール・今後の予定 | 確定日程／検討中 | **高**（予定時期の食い違いの検出） |
| アジェンダ・共有メモ（原文） | 会議前のメモ | 低 |

古い議事録は Notion のミーティングノート（文字起こし）だけで、この節構成が無いことがある。その場合は本文全体を読む。

## 返す形

事実1件＝1行で、`開催日｜会議体｜事実（一文）｜議事録 URL`。解釈や評価を混ぜない。

## 制約

- 顧客の PII が本文にあっても、返す事実に写さない（医療機関名は可）
- 書き込みはしない
