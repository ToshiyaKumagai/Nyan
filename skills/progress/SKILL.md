# 入力を読み、節目に当て、ページに書く（プロセス層）

引数：`$ARGUMENTS`

参照するスキル（中身をここに写さない）：標準の読み方 → `flow-donyu`／議事録 → `tool-notion-minutes`／タスク表・論点シート・Slack・IT基盤 → `tool-project-sources`／マイルストーン DB → `tool-notion-milestone-db`

## 原則

- **判断できる情報が無ければ判断しない。** 「事実確認をお願いしたいこと」に置いて人に返す。推定で埋めない
- 根拠 URL を付けられない○×は付けない。入力に**無い**ことは × の根拠にしない（未確認）
- 本体はページ、プロパティは要約
- 人の書き込みを上書きしない。人が直していたら「レビュー」節に記録し、その値を起点にする

## 手順

1. **範囲。** マイルストーン DB の「最終更新」以降を対象。`--since` があれば優先。初回は全件
2. **入力を読む。** 議事録は本文（AI サマリで代用しない）。タスク表・論点シート・Slack・IT基盤は渡された所在から読む。読めなかった入力は記録し、その入力に依る行は未確認にする
3. **節目に当てる。** 各行の「標準の節目」で `flow-donyu` のカードを引き、事実を受け入れ条件の行に当てる。当たらない事実は「7領域に当てはめられなかった事実」へ（捨てない）
4. **行ごとに状態と信号。** 状態：○／×／未確認／特定不能／対象外。信号：下の表
5. **総合評価。** 下の表
6. **タスク。** 節目ごとに (a) タスク表で進行中のタスクの現状、(b) 議事録・Slack で完了・変更が読めるのにタスク表が更新されていないタスク、(c) 未達・未確認から導く次にやるべきタスク（担当の目安・期限の目安＝逆算の観点）。**タスク表は書き換えない**（提案として書く）
7. **書く前に見せる。** 節目ごとの変更を表で出す。`--dry-run` ならここで止まる
8. **書く。** 「現状」「ギャップと打ち手」「事実確認」「タスク」は置き換え、「更新履歴」に追記、プロパティに要約（`tool-notion-milestone-db`）
9. **差分を返す**（`notify` の入力。更新／事実確認／タスクの3種）

### `--review` のとき

1. 各ページの「レビュー」節と、ページのコメントを読む（`notion-get-comments`）
2. 指摘ごとに該当の節を直す。同意できない指摘は直さず理由を書く
3. 「レビュー」節に「指摘 → 対応（日付）」を追記する。黙って無視しない

## 評価の規約（起案者の叩き台。2026-09-24。変えるときはここだけ直し CHANGELOG.md に1行）

行（受け入れ条件）ごとの信号：

| 信号 | 条件 | 対応 |
| --- | --- | --- |
| 🔴 要介入 | 最低基準が未達で、チーム外の介入の判断が必要 | 打ち手について時間を設けて議論する |
| 🟡 要観察 | 達成の根拠が無い／曖昧（未確認・特定不能、または × だが期限内） | 要注意対象として報告 |
| 🟢 経過観察 | 最低基準を達成している（○） | 報告のみ |

「チーム外の介入が必要」の見分け：逆算の観点の期限を過ぎている／未達だと起きることが医療安全・法令・請求に触れる／受け皿が経営か病院全体。いずれかで 🔴、いずれも無ければ 🟡。

節目の総合評価：

| 総合評価 | 条件 | 対応 |
| --- | --- | --- |
| 🔴 要介入 | 🔴 の行が1つでもある | MTG を設ける。どこに何が介入すべきか・打ち手は何かを案として書く |
| 🟡 要観察 | 🔴 は無いが 🟡 がある | 🟡 の項目をつぶ立てて報告し、方針を求める |
| 🟢 経過観察 | すべて 🟢（対象外を除く） | 報告のみ |

その他のプロパティ：Status（未着手／準備中＝最初の期限が来た／進行中＝初回開催／完了＝最終回開催／対象外）、事実確認（あり／なし）、予定時期（入力に**日程の確定**があるときだけ更新。食い違いは事実確認へ）。

## ページの節の型（`tool-notion-milestone-db` が置き換える範囲）

```
# 現状
## 受け入れ条件の状態（最新）
| カテゴリ | 受け入れ条件（要約） | 状態 | 信号 | 根拠 | 期限（逆算の観点） |
## 総合評価
🟡 要観察 — （理由を1〜2文）
# ギャップと打ち手
- ギャップ：…
- 打ち手：…（誰が・どこで。受け皿は forums.md）
# 事実確認をお願いしたいこと
- <何を>：<なぜ（記載なし／食い違い／記載が粗い）>。確認先：<フロントが病院に／担当者>
# タスク
- 進行中：…
- 更新されていない：<タスク>（<議事録 M/D> で完了と読める）
- 次にやるべき：<タスク>（目安 M/D まで。担当の目安）
# 7領域に当てはめられなかった事実（追記）
# 更新履歴（追記）
- YYYY-MM-DD：根拠 <議事録 M/D・M/D、タスク表 M/D 時点>。変えたこと：…。読めなかった入力：…
```

## しないこと

- 推定で○×を埋める／無いことを × にする／理想状態で判定する
- 「レビュー」「更新履歴」「当てはめられなかった事実」を書き換える／行を消す
- タスク表・論点シートを書き換える／Slack に投稿する（`notify`）
- 標準の写しを直す
